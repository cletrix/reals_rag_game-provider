O que é RAG?

  • 1
    Retrieval — Recuperação A pergunta do usuário é convertida em vetor (embedding) e os trechos mais similares dos documentos são buscados no banco vetorial.
  • 2
    Augmented — Augmentação Os trechos recuperados são injetados no contexto do prompt enviado ao LLM, fornecendo informação factual e específica.
  • 3
    Generation — Geração O LLM (Groq ou Ollama) gera uma resposta fundamentada nos documentos, citando as fontes encontradas.

Resultado: o modelo responde somente sobre o que está nos seus documentos, sem alucinar conteúdo externo — e ainda cita de onde veio a informação.

Arquitetura do Sistema

🦙

Ollama — LLM Local

ollama.com

O que é

Runtime para modelos de linguagem que roda 100% local. No Mac usa Metal GPU. Nenhum dado sai do seu computador.

Papel no projeto

Gera os embeddings (vetores numéricos dos documentos) via nomic-embed-text. Também pode ser usado como LLM de inferência no modo offline.

Modelos em uso

nomic-embed-text llama3.1:8b qwen2.5:7b

Porta de acesso

Roda na porta 11434 do host. Os containers Docker acessam via host.docker.internal:11434 sem containerizar o Ollama (preserva Metal GPU).

# Instalar e puxar modelos
$ brew install ollama
$ ollama pull nomic-embed-text
$ ollama pull llama3.1:8b
$ ollama list            # ver modelos instalados
$ ollama serve           # inicia o servidor (automático no Mac)
⚡

Groq — Inferência Ultra-Rápida

console.groq.com

O que é

Serviço de cloud com chips LPU (Language Processing Unit) proprietários. Inferência 10-20× mais rápida que GPUs convencionais. Tier gratuito generoso.

Papel no projeto

LLM padrão de inferência quando GROQ_API_KEY está configurado. Recebe o contexto recuperado do Qdrant e gera a resposta final.

Modelo padrão

llama-3.3-70b-versatile mixtral-8x7b-32768 gemma2-9b-it

Switching automático

Se GROQ_API_KEY estiver no .env, usa Groq. Se não estiver, cai automaticamente para Ollama local. Pode trocar pelo painel web.

# .env — escolha do provider
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxx
LLM_MODEL=llama-3.3-70b-versatile

# config.py — lógica de switching
if groq_key:
    Settings.llm = Groq(model=model, api_key=groq_key)
else:
    Settings.llm = Ollama(model=model, base_url="http://host.docker.internal:11434")

Claude Code Harness

Ambiente de execução do Claude como agente de desenvolvimento

Skills

Arquivos .skill (ZIP) com SKILL.md — conhecimento especializado instalável que o Claude invoca automaticamente no contexto certo.

Memory

Arquivos .md em ~/.claude/projects/…/memory/. Persiste preferências, feedbacks e contexto de projeto entre conversas.

Hooks

Comandos shell disparados em eventos (PostToolUse, etc.) via settings.json. O harness executa, não o Claude.

Agentes / Subagentes

Claude pode spawnar agentes especializados (Explore, Plan, claude-code-guide) em paralelo para tarefas independentes.

MCP Servers

Model Context Protocol — ferramentas externas (Docker, Redis, Gmail, Drive) expostas como funções para o Claude invocar durante a conversa.

Permissões

settings.json define o que pode ser executado automaticamente. Ações destrutivas ou com blast-radius alto pedem confirmação.

Estrutura Docker

Como funciona a Tokenização

A frase abaixo é quebrada em tokens antes de entrar no modelo:

Quais#1
são#2
os#3
slots#4
mais#5
populares#6
?#7

Embedding (Ollama)

Cada token vira um número. O modelo nomic-embed-text transforma o texto em um vetor de 768 dimensões. Textos similares têm vetores próximos no espaço.

Chunking (LlamaIndex)

Documentos são divididos em pedaços de 1024 tokens com sobreposição de 200 tokens para não perder contexto entre chunks.

Context Window

O LLM tem um limite de tokens por request. O sistema recupera apenas os similarity_top_k=2 chunks mais relevantes para caber no contexto.

tokens_total no banco

Cada query salva tokens_total no PostgreSQL, permitindo monitorar consumo e custo ao longo do tempo.

Onde os Dados são Armazenados

📁 Sistema de Arquivos

PastaConteúdo
data/raw/PDFs, MDs, TXTs — docs originais
data/indexed.jsonMapa arquivo → mtime (controle de re-index)

qdrant_data/Volume persistido do Qdrant (vetores)
postgres_data/Volume persistido do PostgreSQL

🗄️ Bancos de Dados

Qdrant (vetor)

Collection landf_docs — armazena vetores de 768d + metadados (file_name, page_label, texto do chunk). Busca por similaridade cosine.

PostgreSQL (relacional)

Tabelas queries (histórico de perguntas/respostas) e settings (config dinâmica: provider, modelo, top_k). Persistido em postgres_data/.

✓ Qdrant data → ./qdrant_data (host volume, sobrevive restart)
✓ Postgres data → ./postgres_data (host volume, sobrevive restart)
✓ Docs raw → ./data/raw (montado em todos containers que precisam)

Lista de Comandos

# ─── SETUP INICIAL ────────────────────
$ ollama pull nomic-embed-text
$ ollama pull llama3.1:8b
$ docker compose up -d qdrant postgres

# ─── INDEXAR DOCUMENTOS ───────────────
$ cp meu-doc.pdf data/raw/
$ docker compose run --rm rag python ingest.py

# ─── INTERFACE WEB ────────────────────
$ docker compose up -d
$ open http://localhost:2468

# ─── QUERY INTERATIVO (CLI) ───────────
$ docker compose run --rm -it rag
# ─── MAKEFILE SHORTCUTS ───────────────
$ make up          # sobe tudo
$ make down        # para tudo
$ make ingest      # indexa docs novos
$ make query       # abre CLI de query
$ make logs        # logs dos containers
$ make web         # abre o navegador

# ─── MONITORAMENTO ────────────────────
$ docker compose logs -f web
$ open http://localhost:6333/dashboard
$ ollama ps        # modelos carregados

# ─── POSTGRES DIRETO ──────────────────
$ docker exec -it landf_postgres psql -U rag ragdb
ragdb=# SELECT count(*), llm_provider FROM queries GROUP BY 2;

Fluxo de Indexação

Incremental

Apenas arquivos novos ou modificados (via mtime) são reindexados. Arquivos já indexados são pulados automaticamente.

Estimativa de tempo

Antes de indexar, calcula chunks reais e exibe estimativa baseada na velocidade medida anteriormente em embed_speed.json.

Dashboard

Progresso visível em localhost:6333/dashboard do Qdrant e nos logs do container landf_rag.

Fluxo de Query

similarity_top_k = 2
response_mode = compact
streaming = true (web)
fontes rankeadas por score
elapsed_ms salvo no PG
